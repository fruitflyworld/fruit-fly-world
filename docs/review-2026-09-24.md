## 1. What the project is

A browser survival game (a fruit fly in a dish that wants it dead: forage,
dodge a predator, convert energy into eggs, draft one mutation per
generation) whose real product is a **closed-loop exam for judgment models**:
"Don't exam the model. Starve it." The fly's brain is a slot — manual /
evolved genes / a 24-neuron spiking circuit / a judgment layer (free local
heuristic by default; a pinned remote model via a same-origin proxy if the
player brings a key). Every decision is sealed into a hash-chained log.

The differentiator this month: **bit-exact determinism, proven end-to-end**.
Same seed + same brain = byte-identical decision logs on arm64 Chrome, x64
Node, and the production server.

## 2. What is LIVE today (all verifiable)

### 2.1 The game — fruitfly.world/play
- 50-second generations, three food tiers (sugar +12 safe / yeast +26 risky /
  rotten fruit +38 exposes you 6 s), telegraphed predator lunges, an escape
  reflex wired through a leaky-integrate-and-fire "Giant Fiber" driven by
  LC4 (angular velocity) + LPLC2 (looming) — connectome-inspired, honestly
  labelled as such.
- Four selectable brains; per-generation mutation drafts (seeded, pure
  `draftCards`); downloadable decision logs (`flyline-log/1`, FNV-1a
  content hashes); visible wild-type rival; death replay; share cards.
- Agent lane: `public/skill/ffw-dish/` (SKILL.md contract + zero-dependency
  headless-Chrome runner) and an in-page `FlyLabAPI` with
  `autopilot({seed, brain, gens, policy})` at a fixed 60 Hz. Two independent
  AIs have cold-started the skill successfully.

### 2.2 The exam room — /play?bench=1
- Pauses rendering, runs the same (seed, brain, generations) twice at a
  fixed 60 Hz, compares every decision hash, prints IDENTICAL.
- Beacon seeds: `?seed=beacon` derives the exam seed from the latest
  Sepolia block via `/api/beacon` (dual-RPC, 12 s cache). Public randomness;
  honestly labelled "a sample, not a verdict" (12 s blocks are grindable).
- Death calibration: each brain's own danger reads scored against reality
  (Brier); method published at /calibration.

### 2.3 Server-side replay & grading — POST /api/exam/replay
- The server imports `public/play/js/world.js` **from disk at runtime** (the
  exact bytes the browser runs — one-way vendor flow, sha256-locked in CI),
  replays any deterministic lineage, and grades a submitted claim field by
  field (match/mismatch). Rate-limited 10/min/IP, cached by (seed, brain,
  gens).
- Verified live: `{"seed":42,"brain":"judgment","gens":2}` → 19 eggs,
  logHashes 38834a61 / cf59f7a7, `worldVersion: "dish/3"`.

### 2.4 Determinism receipts — docs/determinism.md
- Six leaks found and fixed, each with the measurement: novelty-memory
  carryover, rival-traits-on-wrong-object, predator residue, GF membrane
  carryover, rival genes derived from the visitor's save file (dish/2),
  and **libm last-ulp drift** (dish/3): `Math.sin/cos/exp` differ in the
  final ulp on ~3% of inputs and `Math.atan` on 5.6% between arm64 Chrome
  and x64 Node; one ulp amplified into a 3-egg divergence.
- Fix: `dmath.js` — hand-rolled IEEE-pinned kernels (dsin/dcos/dexp/datan)
  for the simulation lane only; render keeps `Math.*`.
- Receipts: pinned goldens (escape 100%/68% swapped-wiring assay, CX trace
  9fb9e0d0, drafts 0f4d39c3, rival genes e9b1d202) survived the kernel swap
  bit-identically; a 60-case golden baseline (3 brains × 20 seeds × 3 gens,
  arm64 Chrome vs x64 Node) is **1260/1260 field-checks identical**.

### 2.5 The weekly race BACKEND — /api/race (live, no frontend, no entries)
Protocol race/1, mirroring the audited contract:
1. **Commit** (EIP-191 signed): server stores ONLY the sha256 commitment of
   a declarative draft-preference policy — never plaintext. One wallet per
   epoch-aligned week; last 24 h of the week is the draw/reveal window.
2. **Draw**: exam seed derived from the latest Sepolia block mined after
   the cutoff (post-cutoff block hash → FNV-1a → uint32).
3. **Reveal**: must hash-match the commitment or the entry is voided.
4. **Grade**: server replays every revealed entry through the same vendored
   world.js — same seed for all — ranks by eggs → survived generations →
   earliest commit. Lazy grading on read; operator route behind
   RACE_OPERATOR_TOKEN.
- Design choice reviewers should attack: **policies are ordered trait-id
  preference lists, not code** — no untrusted execution on the server.
- Status: `GET /api/race` live (week 2960, phase "commit", 0 entries).
  Tables auto-created in Postgres. No UI, no announcement, no race has run.

### 2.6 The Genesis Passport (live since earlier)
- Soul-bound ERC-721 + ERC-5192 on **Robinhood Chain mainnet (4663)**,
  immutable, 4,444 cap, quest-gated freemint + mandatory X quote post,
  server-side daily cap. One minted. Nothing in the game depends on it.

## 5. The decisions we want reviewed

A. **Sequencing** — which order maximizes honest momentum?
1. Deploy FlyNFT/FlyToken/WeeklyRace to Robinhood Chain and open race week 1
   (needs: commit/reveal UI on /play, operator runbook, FLY pool funding
   decision). Risk: first race with ~0 entrants looks empty; token optics
   before an audience.
2. Ship the race as **bragging-rights-only** first (no token, no NFT): the
   fairness protocol is fully live server-side; only a UI is missing.
   Contracts stay design-only until there are players.
3. Ignore the race; market the determinism receipts (docs/determinism.md is
   promotion-ready) to the eval-crowd; build audience first.

B. **Fly genes are not yet first-class in the sim.** The player fly's
   steering weights are a constant (`PLAYER_GENES`); NFT lineages store 5
   weights nothing reads yet. Options: add an additive `playerGenes` option
   to world.js (bumps WORLD_VERSION to dish/4, regenerate baseline) so a
   lineage is truly what races; or keep race entries = (brain, policy) and
   demote NFT genes to metadata. This is the biggest coherence gap we know
   of between pitch and code.

C. **Oracle (remote-model) runs are sealed, never replayed.** The race
   accepts deterministic brains only (genes/circuit/judgment-local). Is that
   the right line, or should sealed-oracle entries race in a separate lane?

D. **Where does the FLY pool come from and who is the race owner key?**
   Currently: owner = operator EOA, pool = whatever the operator funds.
   Multisig? Anyone's call.

E. **Legal posture**: user has explicitly set legal concerns aside ("don't
  consider legal for now"); copy still says nothing-on-sale and fake-token
  warning. If contracts deploy, that copy flips to live-token copy — the
  securities question is deliberately out of scope of this package but the
  reviewer should flag anything that changes under deployment.

## 6. What we deliberately did NOT do

- No central public leaderboard for bench runs yet (local-only boards).
- No CI replay of cross-architecture parity (goldens are frozen JSON).
- No token deployment, no sale, no presale list, no dates promised anywhere.
- The exchange (lineage shares) exists only as roadmap prose.
