## 2. What changed, and how to check each item

### 2.1 The seal: SHA-256 for new seasons (`market/2`)

A 32-bit FNV-1a head is a checksum, not a commitment: a laptop can grind a different record with the
same eight hex digits, so "sealed" was a word rather than a property.

- `app/lib/market/hash.ts` — plain-JS SHA-256 plus the canonical-JSON rule `market/1` already used.
  No `SubtleCrypto` (async, and different in Node): the browser replay and the server must run
  identical code.
- `app/lib/market/engine.ts` — `versionForSeason()`; `market/2` seals the record hash and the chain
  head with SHA-256 (64 hex digits).
- **The switch is a season boundary: season 3, 2026-10-13 00:00 UTC.** Seasons 0–2 keep the exact
  bytes they already published. A head that strangers have already replayed is not ours to improve.

```bash
npm test        # 134 → 147 tests, including sha256Hex vs node:crypto for 8 inputs and market/2 goldens
npm run verify:anchors -- --all --chain   # → IDENTICAL for each anchored season
curl -s "https://fruitfly.world/api/fly/dusty?season=0&tick=2000" | grep -o '"chain":"[0-9a-f]*"'
# "chain":"003ad503"   ← unchanged, still market/1
```

## 3. What does NOT hold

- **No token exists.** `$FLY` is not live; the chain and venue are placeholders. Nothing is on sale
  and nothing is mintable.
- **The Passport is not deployed for use.** The contract is written and forge-tested; a test
  deployment exists on chain and is disclosed, but it mints nothing and the address placeholder is
  still a placeholder.
- **The seal's remaining trust:** the anchors prove that a head this code recomputes equals the memo
  on chain. Who writes that memo is a hot key on one server, once a day; there is no consensus, and
  the anchor wallet could in principle be used to write a memo for a day that never happened.
  `anchor.ts` refuses duplicates and unclosed days, but the guarantee is "code == chain", not
  "no operator exists".
- **Seasons 0–2 are FNV-1a.** They are pinned and published; that is a deliberate refusal to rewrite
  history, not an oversight.
- **Not built, and said so in STATUS.md:** a connectome weight-rebuild script; real-money trading
  (by design — it would need a tape recorder and a commit-before-reveal wallet policy).
- **Next.js advisories stay open on purpose** (every one clears only in Next 15, which also moves
  React 18 → 19 and makes the request APIs async). The decision and its blast radius are in
  `SECURITY.md`; the dependabot PR stays visible.
- **GitHub UI items only a human can do:** pin the four repositories, verify `fruitfly.world` as an
  organisation domain, require 2FA, upload the organisation avatar, set social preview images.

## 4. Mistakes made in this session

  worked when imported by tests and crashed on the server. Fixed in `d5c59a4` after running the
  command on the deployed box.
- The first anchor attempt for season 0 failed transaction simulation (empty logs); retried and
  confirmed. The failure is in `/var/log/ffw-anchor.log`, not erased.
- The x402 price removal initially replaced one of five menu items; corrected in `5ae9d3a`.

## 5. How to score this

```bash
git clone https://github.com/fruitflyworld/fruit-fly-world && cd fruit-fly-world
npm ci && npm test                     # 147 tests
npm run build                          # no .env needed
npm run verify:anchors -- --all --chain   # replays each day, then reads the memo from a public RPC
curl -s https://fruitfly.world/api/fly/dusty?season=0&tick=2000   # "chain":"003ad503"
```

Claims worth attacking, in the order I would attack them:

1. Does the site say anything the code does not do? Look for present-tense promises about the token,
   the Passport or x402.
2. Do the anchors actually exist on chain, and does the memo match the head this code recomputes?
3. Is the manifest a copy of the chain or a claim about it? (`npm run verify:anchors -- --all --chain`
   is the answer.)
4. Are the tests real, or do they assert tautologies? (`tests/anchors.test.ts` recomputes every entry;
   `tests/anchor-send.test.ts` asserts the transaction without a chain.)
5. Is anything claimed as verified that is only asserted? See §3 — the operator's honesty is the
   boundary, and it is written down rather than implied.
